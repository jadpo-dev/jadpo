# `test.subscriber_failed`

A subscriber failed for good during a test, or its rerun no longer matched the record of its steps.

## Why Jadpo refuses it

In a test, what a step emits is delivered before the next line runs, so a
subscriber's failure is part of what the step did. A delivery that fails
for good, because its failure isn't worth retrying, on its last attempt or
on a fault, ends the test, since whatever the test checked next would rest
on work that never happened. The report names the event, the subscriber
and the attempt, then the failure as
[`test.unexpected_failure`](../errors/test.unexpected_failure.md) shows
one.

## What it looks like

A subscriber's action refuses with a failure not worth retrying:

```jadpo check project=e-subscriber-failed file=app.jadpo hidden
application {}
```

```jadpo check project=e-subscriber-failed file=domains/post/types/address.jadpo hidden
/// Where a parcel goes.
type Address = Text {
    min_length: 1
    max_length: 200
}
```

`domains/post/actions/label.jadpo`:

```jadpo check project=e-subscriber-failed file=domains/post/actions/label.jadpo
use post/entities { Parcel, ParcelNotFound }
use post/types { Address }
use post/failures { NoSuchPlace }

/// Labels a parcel for its round.
action label(parcel_id: Parcel.id, address: Address) fails ParcelNotFound, NoSuchPlace -> Unit {
    if (address == "The Moon") {
        reject NoSuchPlace {}
    }
    attempt Parcel.update(parcel_id) {
        set: {
            labelled: true
        }
    }
}
```

`domains/post/subscribers/label_handed_in.jadpo`:

```jadpo check project=e-subscriber-failed file=domains/post/subscribers/label_handed_in.jadpo migrate=initial
use post/actions { label }

/// Labels each parcel handed in.
subscriber label_handed_in {
    on: ParcelHandedIn
    run: label(event.parcel_id, event.address)
}
```

`domains/post/actions/hand_in.test.jadpo`:

```jadpo check project=e-subscriber-failed file=domains/post/actions/hand_in.test.jadpo expect=test.subscriber_failed
use post/entities { Parcel }

test "a parcel for the moon is taken in" {
    var parcel: Parcel = hand_in("The Moon")
    assert parcel.labelled == false
}
```

`(agent)` at the end of the `next:` line means your coding agent can make
the fix itself.

A delivery stopped as `diverged`, its rerun no longer matching the record
of its steps, is this error too, and the report says so on its `delivery:`
line.

## How to fix it

**If nothing is wrong with what was delivered**, stop the action refusing
it:

```jadpo check project=e-subscriber-failed-fix file=domains/post/actions/label.jadpo
use post/entities { Parcel, ParcelNotFound }
use post/types { Address }

/// Labels a parcel for its round.
action label(parcel_id: Parcel.id, address: Address) fails ParcelNotFound -> Unit {
    attempt Parcel.update(parcel_id) {
        set: {
            labelled: true
        }
    }
}
```

**If it should have been refused at the start**, refuse it in the action
the caller calls, so the subscriber never receives it:

```jadpo check project=e-subscriber-failed-fix-2 file=domains/post/actions/hand_in.jadpo
use post/entities { Parcel }
use post/types { Address }
use post/failures { NoSuchPlace }
use post/events { ParcelHandedIn }

/// Takes a parcel in; labelling it follows in a subscriber.
action hand_in(address: Address) fails NoSuchPlace -> Parcel {
    if (address == "The Moon") {
        reject NoSuchPlace {}
    }
    var parcel: Parcel = Parcel.create {
        set: {
            address: address
            labelled: false
        }
    }
    emit ParcelHandedIn {
        parcel_id: parcel.id
        address: parcel.address
    }
    return parcel
}
```

