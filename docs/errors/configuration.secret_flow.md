# `configuration.secret_flow`

Your code reads a secret setting somewhere other than the few places where Jadpo keeps it on the server.

## Why Jadpo refuses it

A setting marked `secret: true`, such as a password or an API key, must
never leave the server. Jadpo takes a secret only where it uses the value
itself: a connection's `url:`, an integration's `credential:`, an
authentication `signing_key:` and a `crypto` call's `key:`.

Anywhere else, your code could leak it. Returning it, storing it, logging
it, putting it in a failure or building another value from it could all
show it to someone. Even comparing it is refused, because each yes-or-no
answer gives the secret away one guess at a time.

## What it looks like

main.jadpo:

```jadpo check project=e-secret-flow expect=configuration.secret_flow
type PartnerKey = Text {
    min_length: 8
}

config {
    api_key: PartnerKey {
        secret: true
    }
}

function expose_secret() -> PartnerKey {
    return config.api_key
}
```


## How to fix it

The question is what the secret is for.

**If it is the key for an outside API**, give it to the connection that
calls that API, as its `credential:`, and delete the function that read
it. In `app.jadpo`:

```jadpo fragment
            credential: config.api_key
```

```jadpo check project=e-secret-flow-credential file=app.jadpo hidden
application {
    connections: {
        partner: {
            package: Partner.v1
            domains: [orders]
            credential: config.api_key
            environment: config.partner_environment
        }
    }
}
```

```jadpo check project=e-secret-flow-credential file=config.jadpo hidden
use orders/types { PartnerKey }

config {
    api_key: PartnerKey {
        secret: true
    }
    partner_environment: ProviderEnvironment
}
```

```jadpo check project=e-secret-flow-credential file=domains/orders/types/partner_key.jadpo hidden
/// The key the partner gave us.
type PartnerKey = Text {
    min_length: 8
}
```

```jadpo check project=e-secret-flow-credential file=shared/providers/partner/v1/package.jadpo hidden
/// A partner's API.
package Partner.v1 {
    licence: Licence.proprietary
    jadpo: "1.0"
}
```

```jadpo check project=e-secret-flow-credential file=shared/providers/partner/v1/provider.jadpo hidden
/// A partner's API.
provider {
    protocol: Protocol.json_http
    hosts: {
        live: "https://api.partner.example"
        sandbox: "https://sandbox.partner.example"
    }
    credential: CredentialScheme.bearer
}
```

```jadpo check project=e-secret-flow-credential file=network.jadpo_record hidden
// Generated by Jadpo from the hosts the app can reach; update it with `jadpo records update`, never by hand.
record network 1

connection partner
    for Partner.v1
    host https://api.partner.example
    host https://sandbox.partner.example
```

Jadpo sends the key with each call the `partner` connection makes, and
your code never holds it. A database address goes to a connection's
`url:` in the same way, and a signing or encryption key to a `crypto`
call's `key:`.

**If the value is public**, it isn't a secret, so delete `secret: true`.
The setting becomes:

```jadpo fragment
    api_key: PartnerKey
```

```jadpo check project=e-secret-flow-public hidden
type PartnerKey = Text {
    min_length: 8
}

config {
    api_key: PartnerKey
}

function expose_secret() -> PartnerKey {
    return config.api_key
}
```

Your code may now read, return and log `config.api_key` like any other
setting, so do this only for a value anyone may see.
