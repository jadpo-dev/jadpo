# `record.edited`

A record file that Jadpo writes holds something Jadpo couldn't have written, or can't be read.

## Why Jadpo refuses it

A record is a file Jadpo writes from your code and you commit with it, so a
change to one always means the source or a command changed it. A comment or a
tidied line would make its diff mean something else, and the next write would
lose the edit anyway.

`jadpo check` fails while a record is edited, and `jadpo test` and `jadpo dev`
still run.

## What it looks like

Someone added a note to the record of an API:

```jadpo check project=e-record-edited file=app.jadpo hidden
application {}
```

```jadpo check project=e-record-edited file=policy.jadpo hidden
use memos

policy {
    actions: {
        memos.add_memo: [Access.public]
    }
}
```

```jadpo check project=e-record-edited file=domains/memos/types/memo.jadpo hidden
type Memo = Text {
    max_length: 200
}
```

```jadpo check project=e-record-edited file=domains/memos/types/memo_view.jadpo hidden
use memos/types { Memo }

type MemoView = Output {
    text: Memo
}
```

```jadpo check project=e-record-edited file=domains/memos/actions/add_memo.jadpo hidden
use memos/types { Memo, MemoView }

type AddMemo = Input {
    text: Memo
}

action add_memo(input: AddMemo) -> MemoView {
    return MemoView {
        text: input.text
    }
}
```

```jadpo check project=e-record-edited file=domains/memos/routes/memos.jadpo hidden
use memos/types { MemoView }
use memos/actions { AddMemo, add_memo }

routes Memos {
    prefix: /memos

    POST / {
        authentication: RouteAuthentication.none
        input: AddMemo
        output: MemoView
        run: add_memo(input)
    }
}
```

api/main.jadpo_record:

```jadpo check project=e-record-edited file=api/main.jadpo_record expect=record.edited
// Generated by Jadpo from the routes of API main; update it with `jadpo api update`, never by hand.
record api 1

POST /memos
    authentication none
    input AddMemo (body)
    output MemoView
    // Clients rely on 200 here.
    status 200

GET /openapi.json
    generated openapi
    authentication none
    status 200

input AddMemo
    text: Text { max_length: 200 }

output MemoView
    text: Text { max_length: 200 }
```

```text output
error: `api/main.jadpo_record` was edited by hand: a comment isn't part of a record
 --> api/main.jadpo_record:8:1
  |
8 |     // Clients rely on 200 here.
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ not what Jadpo writes
  reason: Jadpo writes this record with `jadpo api update`, and a record is never edited by hand, so its diff always means what the source or a command changed.
  next: Run `jadpo api update`, which writes it again (agent)
  rule: record.edited
  help: https://jadpo.dev/docs/errors/record.edited

check failed: 1 error, 6 files
```

`(agent)` at the end of the `next:` line means your coding agent can make
the fix itself.

A ledger, a list of one-line entries such as the identity registry, is held to
the order Jadpo writes it in. A merge can leave its lines out of order:

```jadpo check project=e-record-edited-order file=domains/memos/actions/keep.jadpo hidden
use memos/types { Memo, Note }

action keep(memo: Memo, note: Note) -> Unit {}
```

```jadpo check project=e-record-edited-order file=app.jadpo hidden
application {}
```

```jadpo check project=e-record-edited-order file=domains/memos/types/memo.jadpo hidden
type Memo = Text {
    max_length: 200
}
```

```jadpo check project=e-record-edited-order file=domains/memos/types/note.jadpo hidden
type Note = Text {
    max_length: 200
}
```

database/identities.jadpo_record:

```jadpo check project=e-record-edited-order file=database/identities.jadpo_record expect=record.edited
// Generated by Jadpo from renames and moves; update it with `jadpo rename`, `jadpo domain` or `jadpo fmt --layout`, never by hand.
record identities 1

type memos.Note -> Note
type memos.Memo -> Memo
```

```text output
error: `database/identities.jadpo_record` was edited by hand: its lines aren't in the order Jadpo writes them
 --> database/identities.jadpo_record:4:1
  |
4 | type memos.Note -> Note
  | ^^^^^^^^^^^^^^^^^^^^^^^ not what Jadpo writes
  reason: Jadpo writes this record with `jadpo rename`, `jadpo domain` or `jadpo fmt --layout`, and a record is never edited by hand, so its diff always means what the source or a command changed.
  next: Run `jadpo records update`, which writes it again (agent)
  rule: record.edited
  help: https://jadpo.dev/docs/errors/record.edited

check failed: 1 error, 4 files
```

Two lines for one thing, such as one type renamed two ways on two branches,
are left for you to settle, since Jadpo can't tell which is right:

```jadpo check project=e-record-edited-line file=domains/memos/actions/keep.jadpo hidden
use memos/types { Memo, Note }

action keep(memo: Memo, note: Note) -> Unit {}
```

```jadpo check project=e-record-edited-line file=app.jadpo hidden
application {}
```

```jadpo check project=e-record-edited-line file=domains/memos/types/memo.jadpo hidden
type Memo = Text {
    max_length: 200
}
```

```jadpo check project=e-record-edited-line file=domains/memos/types/note.jadpo hidden
type Note = Text {
    max_length: 200
}
```

database/identities.jadpo_record:

```jadpo check project=e-record-edited-line file=database/identities.jadpo_record expect=record.edited
// Generated by Jadpo from renames and moves; update it with `jadpo rename`, `jadpo domain` or `jadpo fmt --layout`, never by hand.
record identities 1

type memos.Note -> Jotting
type memos.Note -> Note
```

```text output
error: `database/identities.jadpo_record` was edited by hand: `type memos.Note` is on lines 4 and 5: two renames of one thing, as a merge of two branches can leave
 --> database/identities.jadpo_record:5:1
  |
5 | type memos.Note -> Note
  | ^^^^^^^^^^^^^^^^^^^^^^^ not what Jadpo writes
  reason: Jadpo writes this record with `jadpo rename`, `jadpo domain` or `jadpo fmt --layout`, and a record is never edited by hand, so its diff always means what the source or a command changed.
  next: Put line 5 back as Jadpo wrote it, with `git restore database/identities.jadpo_record` or by hand (agent)
  rule: record.edited
  help: https://jadpo.dev/docs/errors/record.edited

check failed: 1 error, 4 files
```

An edit Jadpo could have written, such as `status 200` changed to
`status 201`, is told by the base commit, the default branch at its merge
base. `jadpo check` builds it, and an entry of a view that changed since
then, where the code behind it gives the same as it did there, was edited
by hand:

```text
error: `api/main.jadpo_record` was edited by hand: `POST /memos` changed since main at 1a2b3c4, and the routes didn't
 --> api/main.jadpo_record:8:1
  |
8 |     status 201
  | ^^^^^^^^^^^^^^ not what Jadpo writes
  reason: Jadpo writes this record with `jadpo api update`, and a record is never edited by hand, so its diff always means what the source or a command changed.
  next: Run `jadpo api update`, which writes it again (agent)
  rule: record.edited
  help: https://jadpo.dev/docs/errors/record.edited
```

An entry added or removed by hand says so: "`GET /memos` was added since
main at 1a2b3c4, and the routes don't have it". Without a base to compare
with, such an edit reads as [`record.out_of_date`](record.out_of_date.md),
which names the same command.

A record that can't be read at all, such as a file that isn't UTF-8 or a
`jadpo.lock` with a line Jadpo can't read, is this error too, and it says what
is wrong.

## How to fix it

**If a record's next step names a command**, run it in the project's folder:

```sh
jadpo api update
```

The record is written again from the code, without the edit. A change the
record needs comes from a change to the routes. For a ledger, the command is:

```sh
jadpo records update
```

Every record is written again, with a ledger's lines in the order Jadpo keeps
them. Commit the result.

**If two lines disagree, or a line can't be read**, restore the file, then make the change again:

```sh
git restore database/identities.jadpo_record
```

The file goes back to its last committed version. Run
`jadpo records` to see what is wrong with any other record. `jadpo.lock` is
checked the same way.
