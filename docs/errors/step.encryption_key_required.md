# `step.encryption_key_required`

An action makes several changing calls, but the app names no key to encrypt the answers it keeps from them.

## Why Jadpo refuses it

When an action makes several changing calls, Jadpo keeps each call's
answer until the action commits, so a retry can replay it rather than
send the call again. Those answers can hold anything a provider sends
back, so they are kept encrypted, with the `SigningKey` setting that
`application { steps: { encryption_key: } }` names. Without one there
is no key to encrypt them with. Jadpo won't make up a secret for you:
the setting is a new value each environment has to be given. The error is
reported once, at the first action that needs the key.

## What it looks like

domains/bakery/actions/file_prices.jadpo, in a bakery app that names no
key in `app.jadpo`:

```jadpo check project=e-step-encryption-key-required file=app.jadpo hidden
application {
    connections: {
        main: {
            driver: Driver.postgres
            url: config.main_url
        }
        sheets: {
            driver: Driver.disk
            path: "/var/lib/bakery/sheets"
        }
    }
    events: {
        store: main
    }
}
```

```jadpo check project=e-step-encryption-key-required file=config.jadpo hidden
config {
    main_url: PostgresUrl
}
```

```jadpo check project=e-step-encryption-key-required file=domains/bakery/types/price_list.jadpo hidden
/// A supplier's prices, one line for each loaf.
type PriceList = Text {
    min_length: 1
    max_length: 2000
}
```

```jadpo check project=e-step-encryption-key-required file=domains/bakery/failures/sheet_not_kept.jadpo hidden

    kind: FailureKind.unavailable
```

```jadpo check project=e-step-encryption-key-required file=domains/bakery/events/prices_changed.jadpo hidden

    price_list: PriceList
```

```jadpo check project=e-step-encryption-key-required file=domains/bakery/events/events.jadpo_record hidden

/// Files each supplier's new prices.
subscriber file_new_prices {
    on: PricesChanged
```

```jadpo check project=e-step-encryption-key-required file=domains/bakery/actions/file_prices.jadpo expect=step.encryption_key_required
use app { sheets }
use bakery/failures { SheetNotKept }
use bakery/events { PricesChanged }

/// Keeps a supplier's new prices as a sheet, then a copy for the
/// accountant.
action file_prices(event: PricesChanged) fails SheetNotKept -> Unit {
    var sheet: File = attempt sheets.put(encoding.to_utf8(event.price_list), FileType.csv) {
        storage_full: SheetNotKept
    }
    var invoice_copy: File = attempt sheets.put(encoding.to_utf8(event.price_list), FileType.csv) {
        storage_full: SheetNotKept
    }
    assert sheet != invoice_copy
}
```

decides a new secret setting that each environment must be given.

## How to fix it

**If these answers should be kept**, name a `SigningKey` setting in
`steps:` in `app.jadpo`:

```jadpo fragment
    steps: {
        encryption_key: config.step_encryption_key
    }
```

```jadpo check project=e-step-encryption-key-required-fix-1 file=app.jadpo hidden
application {
    connections: {
        main: {
            driver: Driver.postgres
            url: config.main_url
        }
        sheets: {
            driver: Driver.disk
            path: "/var/lib/bakery/sheets"
        }
    }
    events: {
        store: main
    }
    steps: {
        encryption_key: config.step_encryption_key
    }
}
```

```jadpo check project=e-step-encryption-key-required-fix-1 file=domains/bakery/types/price_list.jadpo hidden
/// A supplier's prices, one line for each loaf.
type PriceList = Text {
    min_length: 1
    max_length: 2000
}
```

```jadpo check project=e-step-encryption-key-required-fix-1 file=domains/bakery/failures/sheet_not_kept.jadpo hidden
/// The sheets store had no room for a sheet.

    kind: FailureKind.unavailable
    message: "There was no room to keep the sheet."
}
```


```jadpo check project=e-step-encryption-key-required-fix-1 file=domains/bakery/actions/file_prices.jadpo hidden
use app { sheets }
use bakery/failures { SheetNotKept }
use bakery/events { PricesChanged }

/// Keeps a supplier's new prices as a sheet, then a copy for the
/// accountant.
action file_prices(event: PricesChanged) fails SheetNotKept -> Unit {
    var sheet: File = attempt sheets.put(encoding.to_utf8(event.price_list), FileType.csv) {
        storage_full: SheetNotKept
    }
    var invoice_copy: File = attempt sheets.put(encoding.to_utf8(event.price_list), FileType.csv) {
        storage_full: SheetNotKept
    }
    assert sheet != invoice_copy
}
```

Then declare the setting in `config.jadpo`, which becomes:

```jadpo check project=e-step-encryption-key-required-fix-1 file=config.jadpo migrate=initial
config {
    main_url: PostgresUrl
    step_encryption_key: SigningKey
}
```

The answers of `file_prices`'s calls are now kept encrypted with the key
in `STEP_ENCRYPTION_KEY`, which must be at least 32 characters with no
spaces and is checked when the app starts.
