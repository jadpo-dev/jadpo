# `translation.feature_off`

A language file words a Jadpo message of a feature the application has off.

## Why Jadpo refuses it

Jadpo writes the text of a feature, such as the sign-in email for magic
links, only for an application that has the feature. Wording one of its
messages while the feature is off changes nothing a reader ever sees, and
it hides a mistake: the file looks finished, and the feature you expected
isn't on.

## What it looks like

This application signs no one in with magic links, and its root language
file rewords the subject of the sign-in email.

```jadpo check project=e-tr-feature-off file=app.jadpo hidden
application {}

locales {
    default: Locale.en_gb
    supported: [Locale.en_gb]
}
```

`translations/en_gb.jadpo`:

```jadpo check project=e-tr-feature-off file=translations/en_gb.jadpo expect=translation.feature_off
translations {
    jadpo: {
        magic_link_email: "Your link to sign in"
    }
}
```

```text output
error: `magic_link_email` is a message of a feature this application has off
 --> translations/en_gb.jadpo:3:9
  |
3 |         magic_link_email: "Your link to sign in"
  |         ^^^^^^^^^^^^^^^^ a feature this application has off
  reason: `magic_link_email` is part of Jadpo's magic links text, which Jadpo writes when the application signs users in with magic links. This application doesn't, so wording it changes nothing and would hide a mistake.
  next: Remove `magic_link_email` from `translations/en_gb.jadpo`, or switch the feature on (agent)
  rule: translation.feature_off
  help: https://jadpo.dev/docs/errors/translation.feature_off

check failed: 1 error, 2 files
```

`(agent)` at the end of the `next:` line means your coding agent can make
the fix itself.

## How to fix it

**If the application doesn't use the feature**, remove the wording from
`translations/en_gb.jadpo`:

```jadpo check project=e-tr-feature-off-fix file=translations/en_gb.jadpo
translations {}
```

```jadpo check project=e-tr-feature-off-fix file=app.jadpo hidden
application {}

locales {
    default: Locale.en_gb
    supported: [Locale.en_gb]
}
```

The file no longer words anything Jadpo won't write.

**If the application should have the feature**, switch it on. Magic links
are switched on by `magic_link:` in `authentication.jadpo`, and need an
email connection and a `display_name:` as well:

```jadpo fragment
    sign_in: {
        magic_link: {
            link: "/sign-in/confirm"
            same_browser: true
        }
    }
```

```jadpo check project=e-tr-feature-off-on file=authentication.jadpo hidden
use accounts

authentication {
    browser_session: {
        cookie: "notes_session"
        origin: config.browser_origin
    }
    api_token: {}
    sign_in: {
        magic_link: {
            link: "/sign-in/confirm"
            same_browser: true
        }
    }
    on_first_sign_in: accounts.create_member
}
```

```jadpo check project=e-tr-feature-off-on file=config.jadpo hidden
config {
    browser_origin: Url
    mail_sender: Email
    smtp_host: Hostname
}
```

```jadpo check project=e-tr-feature-off-on file=app.jadpo hidden
use accounts/entities { Member }

application {
    display_name: "Notes"
    connections: {
        mail: {
            driver: Driver.smtp
            host: config.smtp_host
        }
    }
    email: {
        connection: mail
        from: config.mail_sender
    }
}

principal {
    user: {
        subject: Member.email
    }
}

locales {
    default: Locale.en_gb
    supported: [Locale.en_gb]
}
```

```jadpo check project=e-tr-feature-off-on file=domains/accounts/entities/member.jadpo hidden
entity Member {
    id: Uuid
    email: Email {
        unique: true
    }

    policy: {
        create: [Access.system]
        read: [id]
    }
}
```

```jadpo check project=e-tr-feature-off-on file=domains/accounts/failures/sign_up_closed.jadpo hidden
/// Signing up is closed for this address.
type SignUpClosed = Failure {
    kind: FailureKind.conflict
}
```

```jadpo check project=e-tr-feature-off-on file=domains/accounts/actions/create_member.jadpo migrate=initial hidden
use accounts/entities { Member }
use accounts/failures { SignUpClosed }

/// Signs a new member up the first time they sign in with a proved address.
action create_member(first: FirstSignIn) fails SignUpClosed -> Member.id {
    if (not first.address_verified) {
        reject SignUpClosed {}
    }
    match first.address {
        none -> {
            reject SignUpClosed {}
        }
        some(address) -> {
            var member: Member = attempt Member.create {
                set: {
                    email: address
                }
                conflict: {
                    Member.email: SignUpClosed
                }
            }
            return member.id
        }
    }
}
```

```jadpo check project=e-tr-feature-off-on file=api/main.jadpo_record hidden
// Generated by Jadpo from the routes of API main; update it with `jadpo api update`, never by hand.
record api 1

api main
    authentication api_token
    authentication browser_session

POST /auth/magic-link
    generated magic link
    authentication none
    input MagicLinkAsk (body)
    status 202

POST /auth/magic-link/confirm
    generated magic link
    authentication none
    input MagicLinkConfirmation (body)
    output MagicLinkConfirmed
    status 200

POST /auth/magic-link/redeem
    generated magic link
    authentication none
    input MagicLinkCode (body)
    output MagicLinkToken
    status 200

GET /openapi.json
    generated openapi
    status 200

output MagicLinkConfirmed
    return_to: Text

output MagicLinkToken
    token: ApiToken
```

```jadpo check project=e-tr-feature-off-on file=translations/en_gb.jadpo hidden
translations {
    jadpo: {
        magic_link_email: "Your link to sign in"
    }
}
```

Magic links are on, and the sign-in email has your subject.
