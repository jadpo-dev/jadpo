# Jadpo 0.3.0

Released 5 November 2026.

This release adds the commands for finding, installing and publishing packages. It checks much more
of how your app handles personal data: what it deletes when a person asks, and which outside
services it sends it to. It also adds passkey confirmation for single requests, encrypted fields
and an audit trail.

A few terms come up below. Erasing a person deletes their personal data when they ask. A connection
is an outside service your app calls, declared in `app.jadpo`. A domain is a part of your app with
its own folder, such as `billing`. An acceptance is a short file in `acceptances/` in which a person
records that they agreed to a change, and why. Jadpo asks for one where the choice is yours, such as
removing data.

## Before you upgrade

These refuse code that 0.2.0 accepted. `jadpo check` names each one, with its fix.

- **Erasing a person clears their contact details.** On a record that is kept after a person is
  erased, an `Email`, `PhoneNumber`, `PersonName`, `PostalAddress`, `GivenName` or `FamilyName`
  field must be optional, so it can be cleared, or say `erase: Erasure.retained`
  (`data.erase_field_required`).
- **Sending an `Email` to an outside service needs an acceptance** when the connection or package
  receiving it doesn't declare `erasure:`, which says how it deletes data on request. That includes
  the recipients of email sent over SMTP (`acceptance.missing`). `jadpo build` checks this too.
- **An `Email` in a prompt to an AI model needs `contact` in the prompt's `allowed:` list**
  (`semantic.ai_field_unmarked`). A route marked `cache: immutable` can't return one
  (`route.cache_invalid`).
- **Schedules, event subscribers and batch jobs only reach data whose access rules grant
  `Access.system`** (`policy.system_grant_missing`).
- **A `File` can't be sent to or received from a provider package, a queue or an AI prompt**, and a
  route can't take or return one yet. Reading a file's fields directly is refused; use the file's
  functions.
- **A migration that removes data needs an acceptance** (`migration.drop_not_accepted`), and so
  does a package upgrade that Jadpo marks as risky.
- **`bytes` is a reserved name**, so a domain or a library can't use it. `ProblemDetails`' field
  `type_` is now `type`.
- **A test can't read a `TestPasskey`'s fields.**

## New

- **Packages.** A package names its publisher with `publisher:`. `jadpo package new` starts one,
  and `jadpo package search`, `add`, `show`, `update` and `remove` work with a registry.
  `jadpo package verify` checks a package the way the registry does, and refuses a proprietary
  licence. You can install packages from your company's own git repositories once someone records
  an acceptance listing them.
- **Personal data.** An email address counts as personal data, and `jadpo check` points out a
  route anyone can call without signing in that returns one. Erasing a person clears their phone
  numbers, names and postal addresses even where you didn't mark them, and erases a record they
  shared once no one else is left on it. `jadpo check` lists every connection and outside address
  that personal data reaches, and asks for a reason when data stays at a connection that can't
  delete it.
- **Passkeys confirm a single request**, such as a payment, on top of signing in.
- **Encrypted fields**, whose keys are kept in your app's database rather than in configuration.
- **An audit trail**: a record's history, kept for as long as you say and erased with the person.
- **Feature flags** can be changed, listed and removed. A test can run with each value of a flag,
  and `GET /flags` returns the caller's flags.
- **Rate limits** on a route or a whole API, with `rate_limit:`.
- **Routes.** A `GET` route can run an action, a function that reads or changes data, when Jadpo can
  prove it only reads. A route can send raw bytes, and say its answer never changes so it can be
  cached.
- **Monitoring thresholds**, such as an error rate that raises an alert, set for each domain.
- **Standard type pages**, one for each of Jadpo's built-in types such as `Email`, also shown by
  `jadpo help <Type>`.
- **The approval report**, the summary a person reads before approving a change to an app, lists
  the decisions first.
- **A reserved word can name a field** or an enum variant.
- **Shorter command output**, with `--full` for everything, and a single error, rather than one per
  test, when the test database doesn't work.

## Fixed

- A route that takes or returns a `File` is refused by `jadpo check`, not when it runs.
- Columns of a PostgreSQL extension's types, such as pgvector's, are read correctly.
