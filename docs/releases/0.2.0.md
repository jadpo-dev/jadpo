# Jadpo 0.2.0

Released 1 November 2026.

This release adds signing in with an outside provider, such as Google, and the first rules for
personal data: records that belong to a person, erasing them when the person asks, and how long
fields are kept. It also adds feature flags, search on PostgreSQL, and guides in the docs.

## New

- **Sign in through a provider.** Jadpo checks a sign-in provider declared with `Driver.oidc`, and
  your app answers the provider's sign-in routes. `jadpo dev` signs you in through a provider with
  an account chooser, and a route test signs in with `test_providers`. An app can also accept tokens
  from an outside issuer, and `on_first_sign_in:` says what happens the first time someone it
  hasn't seen signs in.
- **Person entities.** An entity, a kind of stored record, can say it is a person, and other
  records can belong to one. `User.erase` erases a person's records.
- **Retention.** A field or an entity says how long it is kept, and a schedule deletes what is past
  it.
- **Feature flags.** Declare flags, read them for the caller, and set them in tests.
- **Search on PostgreSQL**, with highlighted matches, ranked and paged results, and your app's
  access rules applied.
- **Files.** A file's bytes are deleted once no record holds the file. Writing a file checks it
  against its field's storage, allowed file types and `max_size:`.
- **Acceptances** for changes a person must agree to: an API change that could break callers,
  wider access, a new outside address, a declined security finding, or a package from git. An
  acceptance is a short file in `acceptances/` that records who agreed and why.
- **Money and measurements.** Using a plain number for an amount of money or a measurement, such as
  kilograms, is an error. You can decline it if you give a reason.
- **`jadpo seed`** fills a database with starting records.
- **Roles from the sign-in provider.** Access rules can use roles that the provider gives a person.
- **Docs.** Guides, each for one job such as adding sign-in, and a generated page for every
  built-in type. The primer, the page a coding agent reads before writing an app, comes with a
  lending desk example.

## Fixed

- `jadpo check` refuses an unknown section of `application { }`, and a test that sets the same
  thing twice.
- `jadpo build` reports a package it can't download as `toolchain.fetch_failed`.
- A migration no longer reports an unchanged column as changed because the fields are in a
  different order.
- Using a security feature that isn't built yet is an error on the line you write it, rather than
  being ignored.
- The VS Code extension has its icon.
