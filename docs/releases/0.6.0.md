# Jadpo 0.6.0

Released 27 November 2026.

This release adds caches and Redis, telemetry sent over OTLP, and outgoing webhooks to the addresses
your customers register. Queries can filter by a related record, search inside text, read every
record that matches and see the records a lifecycle hides. `jadpo explain` gives a coding agent a
map of your app, and `jadpo fix` applies the edits that leave no choice. Some new checks refuse code
Jadpo 0.5.0 accepted, and an `Int` now reaches JSON as a number.

## Before you upgrade

- **A route whose action may set a field nobody may set is refused** (`policy.effect_ungranted`).
  Before, only a field the action always set was. Now a field of a patch's `Input`, and one
  `when_supplied:` sets, are refused too, at check rather than with a 403 when the request supplies
  them. Leave the field out of what the action writes, such as the patch's `Input`. If someone
  should be able to set it, ask the app's owner: letting more callers set a field is a widening a
  person accepts.
- **A restricted field copied through a query's output is checked**
  (`policy.output_field_unproved`). A value read through a query's `Output` is now followed as a
  read from the record, so a copy into a record whose readers may not read the source is refused,
  where 0.5.0 missed it. Copy only what those readers may read, or have a person approve the copy in
  an acceptance, as `"desk.Macro.body -> desk.Reply.body": PolicyChange.field_copied`.
- **A batch that saves no tenant is refused** (`policy.batch_tenant_missing`). In an app with a
  `tenant:`, a batch's run reaches only the tenant its saved values name, so one that saves none
  would walk nothing, every time. Save the tenant's `id` in `from:`, in what `each:` or `finished:`
  captures, or in `key:`. Work for every tenant at once belongs in a schedule's own action.
- **A unique rule over a value with an empty part holds it once, and the next migration checks your
  data** (`migration.apply_failed`). Two `EmailWithName` values with the same address and no name,
  or two choices that leave the same fields empty, used to both get in. The next migration rebuilds
  each such key, and `jadpo migrate apply` refuses while records share a value, naming how many sets
  it found and the first records' `id`s. Change or remove the duplicates, then apply it again.
- **An `Int` with an open side reaches JSON as a number.** A bare `Int`, a count, or an `Int` type
  with only a `min:` used to be sent as a string, `"3"`, and is now `3`. Only a type whose declared
  `min:` or `max:` goes past 2^53 - 1 is still a string. Reading takes either form, but a client that
  parses these fields as strings needs changing. OpenAPI now gives them as `integer`.
- **`rate_limits.counted_in_memory` is retired**, so a `decline` naming it is `decline.unused`.
  Rate limits in a Redis store are now counted in Redis, on Workers too. Remove the decline line.
- **Your own type can't take the name of a new built-in type** (`semantic.duplicate_declaration`).
  `WebhookSecret`, `RegisteredWebhook` and `NormalForm` are now built in. Rename your declaration.
- **`telemetry` is a reserved name** (`semantic.standard_namespace_reserved`). It is the new
  namespace code records metrics through. Rename a declaration, domain, library, parameter or
  variable called `telemetry`. A field or a named argument may still use the word.

## New

- **Caches.** A query's `cache:` keeps a route's results in a Redis store, or with `Driver.memory`
  in each server's own memory, for at most `keep:`, by caller and by arguments. An entity's
  `caches: { records: }` keeps each record whole by `id`, one copy held to policy each time it is
  read. Every committed write, purge and erasure clears what it could have made stale, and a write's
  `Jadpo-Revision` header and cookie make that caller's next read skip older entries. Writes always
  go to the database. `Driver.memory` is reported as `connection.memory_cache` until you decline it,
  since on several servers it serves stale pages.
- **Redis.** `Driver.redis` works natively and on Workers, over TLS. Rate limits counted in it share
  one count and window across every server and Worker instance. An entity can be kept in Redis,
  each record expiring `expires_after:` its last write, read by `id`, by a unique field, and as a page
  or a count by an indexed field. An action's writes to it still commit all together.
- **Telemetry over OTLP.** A `telemetry:` section in `application { }` sends each request's trace,
  metrics and logs as OTLP, from `jadpo dev` and from deployables, to any collector: a vendor is an
  endpoint and a header. You declare metrics in a domain's `monitoring.jadpo`, record them with
  `telemetry.<metric>.add(...)`, and add to a trace with `telemetry.note`. A personal field is
  refused as a label or an attribute. `jadpo traces`, `jadpo metrics` and `jadpo logs` read what
  `jadpo dev` kept.
- **Outgoing webhooks to your customers' addresses.** An entity's `webhooks:` lists the events its
  records' addresses receive, and the generated `register_webhook`, `webhooks` and `remove_webhook`
  keep them under the record's grants. Each address gets a secret of its own, shown once, and each
  event is posted to it signed and retried: HTTPS only, public addresses checked at every attempt,
  and no redirects.
- **Scopes for external tokens.** `external_token: { scopes: }` declares the scopes its tokens
  carry, and an entity's policy names the scope each effect needs with `scopes:`. A scope only ever
  takes away, so a token never reaches more than its person can. Loosening one needs
  `PolicyChange.scopes_loosened`, and a route test gives a token's scopes with `scopes:`.
- **Callers matched by kind.** A `match` on a `Principal` has an arm for each kind of caller,
  `user(name)` or `service(name)`, so one route both kinds call can tell them apart. A
  `Principal.user` or `Principal.service` widens to `Principal`.
- **Filtering by a related record.** `exists(EnquiryTag.enquiry_id, EnquiryTag.tag_id == tag_id)`
  on a query's `where:` keeps the records with a linked record that meets the condition, and
  `not exists(...)` the ones with none. It works on a page and in an aggregate query too.
- **The bin.** `include_hidden: true` on a query, or as the last argument of `exists(...)`, reads
  the records a lifecycle hides as well as the visible ones, so a bin view and a guard such as "no
  tickets, binned ones included" can be written. A transition marked `reaches: hidden` brings a
  hidden record back. It needs the entity's `update:` grants and, when the lifecycle has a `delete`
  transition, its `delete:` grants, so nobody undoes a delete they couldn't have made.
- **`limit: every`.** A query returning a list reads every record that matches, up to 10,000. When
  more match it gives none of them and the action stops with a fault, so a list is never cut short
  and a bulk change made of the query and a loop of writes changes nothing.
- **Searching inside text.** `text.contains_ignoring_case(Todo.title, words)` works on a query's
  `where:` and `where_present:`, through a trigram index the migration makes. `text` gains
  `normalise`, `index_of`, `last_index_of`, `trim_start`, `trim_end`, `pad_end`, `truncate`,
  `equals_ignoring_case` and `contains_ignoring_case`.
- **Ordering by an optional field.** A list or a page can be ordered by an optional field, with
  `none` after every value in both directions.
- **A request with no body.** A blank body reads as `{}` on a route whose input has no field the
  body must send, whatever its `Content-Type` says.
- **Reading another store.** An action can read a second store, in a read-only snapshot of its own,
  beside the transaction of the store it writes. It used to be refused as not built yet.
- **Changing a stored field's type.** A column whose type changes other than by widening moves to a
  new column filled by the backfill, and the old one stays until a later migration drops it, so
  servers still on the old build keep working. `jadpo fix <name> swap` now also swaps a standard type
  in under stored data, and writes the migration that converts each value.
- **Policy that follows what a value is for.** A restricted field used only to choose an existing
  record's `id`, compared with the action's parameters, is a lookup, not a copy, and needs no
  acceptance, nor does a find-or-create built on it. A field that only decides whether an action goes
  ahead, by a check that can only `reject`, is checked once, as the failure it gives. A value copied
  into a record whose owner is the caller, such as a duplicate of their own record, is proved
  against what that caller could read.
- **`jadpo explain`** prints a map of your app, read from what `jadpo check` builds: where the
  product's rules are written, who can call it and how they sign in, each entity with its fields,
  lifecycle and policy, the routes, the background work and the docs topics to read. A coding agent
  reads it before changing an app. `jadpo help topic <id>` prints a docs topic offline.
- **`jadpo fix`**, alone, applies every edit `jadpo check`'s errors carry that leaves no choice,
  checks again and repeats, then lists what it changed. It never writes an acceptance or widens who
  can read or write anything. A failing check shows each edit under `fix`, and its last line says how
  many of the errors `jadpo fix` would fix.
- **`jadpo check` does more of the routine work.** Outside CI it writes the record views and the
  next migration a command would have written, when nothing needs a decision, and says what it
  wrote. Errors only a person can clear are asked once together, as one question with the
  acceptance entries a yes would write.
- **`jadpo fmt`** formats only the files edited since the last commit. `jadpo fmt --all` formats
  every file, and `--check` still reads them all.
- **Agents ask the owner.** The `AGENTS.md` `jadpo new` writes, the agent skill and the primer tell
  a coding agent to stop and ask when a change needs a person's acceptance, contradicts a rule the
  project writes down, or leaves open a case the product's rules would decide, and to ask once,
  with every open point in one question.
- **A generated erasure test.** For each person entity no test erases, `jadpo test` makes the person
  and a record of each kind that belongs to them, erases the person, and checks their export holds
  the records first and nothing after. Generated tests now run inside workerd too.
- **Keeping AI prompts and answers.** `ai: { keep_content: }` keeps each call of the listed prompts
  beside the caller's sessions, sealed, exported and erased with them, and deleted after `keep:`. A
  package's `embed:` with a `batch:` splits `ai.embed_all` across requests.
- **Packages.** `jadpo package conform` runs the `email` and `receiving` suites, and
  `jadpo package check` and `verify` run each capability's suite against the package's recordings
  and a local fake. The registry shows each release's run, pinned to its digest. `jadpo package
  record` writes an operation's output type from the sandbox's answer, and recipes' tests run in
  `sample/`.

## Fixed

- A data builder in a test runs without policy, as a test's own call does. On an entity whose
  `create:` granted no one, `make.<Entity>` used to be refused.
- `Ticket.status(Status.closed)` builds an enum field's type from a value of its enum. It used to be
  refused as `type.constructor_input`.
- A field read through an optional `Page`, such as `response.output.items`, is
  `type.nullable_selection`, with `match` as the fix. It used to pass `jadpo check` and stop the test
  with "not built yet".
- A principal's subject kept in several columns or as JSON is read whole. Sessions, API tokens and
  service keys for such a subject used to answer 503.
- A passing `jadpo check` describes a first commit's records as a notice an agent carries on from.
  It used to print a decision marked `(human)`, which stopped agents on an unchanged app.
- A view of a record Jadpo could have written is `record.out_of_date`, which `jadpo check` writes
  again. It used to be reported as a hand edit.
- The formatter keeps a declaration written inside an entity's braces in its place, keeps a
  snippet's `use` lines after a bare seed or test, and doesn't start a line with `!=` or `in` when it
  removes a `;`.
- Several errors say what they need. A write a `match` is on is told to move into an action of its
  own, `type.mismatch` shows the `list.map` that converts a list, `naming.folded_collision` names
  what to rename, a migration beside other errors says `jadpo check` writes it once they are fixed,
  and the acceptance errors tell an agent to ask its user before drafting one.
- `jadpo help` says a type built on `Text` is text already, rather than pointing at `text.from`.
