# Jadpo 0.5.0

Released 13 November 2026.

This release carries out people's requests to export or erase their data, and keeps files: uploads
go straight to a store, on disk or S3, and downloads go out as signed links. It adds commands that
rename and move code without breaking stored data, and new ways to write and run tests. New checks
keep passwords, secrets and personal data where they belong, and some of them refuse code that
Jadpo 0.4.1 accepted.

## Before you upgrade

- **A field marked `personal:` that nothing reads is refused** (`data.personal_unread`). Personal
  data your app holds and never uses is data it shouldn't hold. Read the field where your app needs
  it, in a query, an output or an action; a test or a fixture reading it doesn't count. If you keep
  it for a legal reason and only an export reads it, put
  `decline data.personal_unread: "<your reason>"` above the field.
- **An action that erases a person needs an erasure log** (`data.erasure_log_required`). The log is
  how Jadpo erases someone again after a restored backup brings them back. Name where it is kept in
  `app.jadpo`, as `privacy: { erasure_log: { store: <connection> } }`: a second database, or a store
  of files, that holds none of the records erasure reaches (`data.erasure_log_store` otherwise).
- **A provider call that sends a `Password` is refused** (`type.password_sent_to_provider`). So is a
  call of a package's action that sends one on. Send the provider something else it takes, such as a
  token it issued. If the call has to carry the password, put a `decline` line with the reason above
  your action, and have a person accept it in an acceptance.
- **A route can't read a secret value from its URL or a header** (`route.secret_outside_body`). A
  `Password`, `TotpSecret`, `SecretText` or `OneTimeCode` comes in the JSON body of a `POST`, `PUT`
  or `PATCH`. A `BearerToken`, `Jwt` or `ApiKey` may also come in a header. A webhook's `reply:` now
  holds no secret value at all (`type.secret_exposed`).
- **A file in `domains/` or `shared/` that no declaration uses is refused**
  (`layout.asset_unreferenced`). Those folders hold your code and the files it uses, such as an
  email's templates. Put the file beside the declaration that uses it, or move it out of the code
  folders.
- **An email needs words for its subject in every locale**. With no `locales { }` in `app.jadpo`,
  `jadpo check` refuses the email (`translation.locales_required`), and a domain with no language
  file for a supported locale is `translation.file_missing`. The email used to fail only when it was
  sent. Declare your locales, and give the email its entry in each domain's language files.
- **`make`, `privacy`, `postal` and `names` are reserved names**
  (`semantic.standard_namespace_reserved`). They are new namespaces: `make` for data builders in
  tests, `privacy` for data requests, and `postal` and `names` in the standard library. Rename a
  declaration, domain, library, parameter or variable called one of them. A field or a named
  argument may still use the word.
- **Your own type can't take the name of a new built-in type** (`semantic.duplicate_declaration`).
  `FileUpload`, `UploadSlot`, `AnyObject`, `PersonErased`, `PersonalDataExport` and the data-request
  types whose names start with `Privacy` are now built in. Rename your declaration.
- **A `decline` line above a field of a value built in a body is refused**
  (`syntax.expected_statement`). Move it above the function or action that builds the value: a
  decline there now covers a finding in that field.

## New

- **Data requests.** `privacy:` in `app.jadpo` generates the routes for a person to ask for an
  export or an erasure of their data: by email address without signing in, signed in, or through
  your staff with `privacy.create_request`. Each request has its one-month legal deadline, an
  alert a week before it and `PrivacyRequestOverdue` once it passes. An erasure waits out a
  cooling-off period, 14 days unless you set it, with a cancel link, and an export is a single-use
  download link. Jadpo generates the endpoints, and your frontend builds the pages.
  `jadpo privacy requests` lists the requests still to finish. Keeping exports needs a store of
  files on the disk driver, which runs on the native target only.
- **`User.export(id)`** gives everything held about a person, in every store, as JSON with your
  API's field names: their record, the records erasure would delete with them, and the records kept
  that refer to those. A `File` in it is a signed link.
- **Erasure reaches further.** `User.erase` now emits `PersonErased`, and after it commits it erases
  the person's records in your other stores and asks each provider whose package declares an
  `erasure:` to erase them, retrying until the provider confirms. It also takes them out of the
  feature-flag tables. Each erasure is logged, and the log is replayed every time the app starts, so
  a restored backup brings nobody back.
- **Personal data in logs and reports.** A failure that ends a route, a delivery or a schedule's run
  is now logged as `failure.rejected`, and that log and an audited entity's history keep a marked
  field only as a keyed hash. Every export, erasure and read of a sensitive field is recorded as an
  access event with no values in it. The personal-data report lists, for each person entity, every
  marked field with who may read it, its retention and what erasure does.
- **Uploads, downloads and S3.** A client uploads a file straight to the store. An action calls the
  generated `Entity.field_upload()` for an `UploadSlot`, the client sends the file to the slot's
  address, and an ordinary create or update attaches it with a `FileUpload`. A field over 100 MB is
  uploaded in parts, and any part can be sent again. A `File` in an output goes out as a signed link
  valid for five minutes. `Driver.s3` keeps files in a bucket on any S3-compatible service, natively
  and on Workers.
- **Files go out with what you send.** A `File` in a provider operation's input or a webhook's reply
  is sent as its bytes, and an email attaches every file a list, set or map field holds.
- **`jadpo files`** lists a store's files, in production or in `jadpo dev`, shows, gets and puts
  one, and copies every file and the erasure log from one store to another.
- **`jadpo rename` and `jadpo domain`.** `jadpo rename` renames a declaration or a field everywhere
  code names it, and moves its file and its test. Renaming in the editor runs the same code.
  `jadpo domain rename`, `split` and `merge` move a domain's files and every call into it. Stored
  data keeps up: a renamed field keeps its column, a renamed entity its table, and a renamed enum
  variant or JSON member the name its stored values hold, so there is nothing to migrate.
- **`jadpo inspect` and `jadpo impact`.** `jadpo inspect` prints the project map: each domain's
  declarations, where each is written and what each calls. `jadpo impact <name>` lists what a change
  to one declaration reaches: the domains that call it, the routes, schedules and subscribers that
  reach it, and the tests that cover it.
- **Data builders and `assert emitted` in tests.** `make.Loan { title: "Middlemarch" }` creates a
  record through the entity's real create and fills each field you leave out with a valid value. It
  can set a lifecycle's state, so a hard-to-reach state is easy to start from.
  `assert emitted OrderPlaced { order_id: order.id }` checks that an event with those fields was
  emitted.
- **Tests generated for each route.** `jadpo test` also runs tests it writes from each route's
  OpenAPI document: that the route refuses bad input with `{ field, rule }`, that each failure it
  lists reaches the client in its envelope, and that it sends nothing its output doesn't declare.
- **New ways to run tests.** `jadpo test --interactive` opens a keyboard view of every test with its
  last result. `--affected` runs the tests that reach what your branch changed. Under `--watch`,
  `enter`, `a` and `f` run tests between saves.
- **Files and providers in tests.** `fixture_file("customers.csv", store: imports)` keeps a file
  from the domain's `fixtures/files/` in the test's store, and `fakes: { imports: unavailable }` or
  `storage_full` makes a store fail. `<connection>.<resource>.<operation>.requests` lists what your
  code sent a provider, typed as the operation's input.
- **Queries and writes over more types.** A query compares and orders standard types, amounts of
  money and values kept in several columns or as JSON, as your code does. A unique rule or an index
  can cover a value kept as JSON, and `IndexKind.json` adds a JSON index. An update by `id` can
  work a value out from stored fields and refuse it by its rule in one statement, as
  `Stock(Product.stock - ordered) { min: OutOfStock }` does, without loading the record. A `geo.`
  condition works in an include or an aggregate query.
- **Migrations and database reports.** `jadpo migrate apply` refits a stored field given a new
  `pattern:`, and applies a computed backfill for a field that allows less, in batches.
  `jadpo migrate new` asks for a missing purpose at a terminal. `jadpo check` writes
  `build/report/database.md` and `queries.md`: every table, column and index with the statements it
  serves. `jadpo sql <query> --explain` shows PostgreSQL's plan for each statement, made on a
  throwaway database.
- **Batches over a provider's list.** The file helpers' writes, such as `csv.write`, can walk a
  provider's list operation page by page, and so can a `batches.each` whose `each:` action calls no
  provider. A query's page of more than 1,000 items is split into batches. `jadpo batches` lists,
  shows and cancels runs.
- **Publishing events to other systems.** `publishing:` in `application { }` posts chosen public
  events to an address through a `Driver.webhook` connection once the action that emits them
  commits, signed as Standard Webhooks signs and retried. Each API's OpenAPI document lists them in
  `x-jadpo-events`.
- **Events and deliveries.** A `GET` route's action may now emit an event, so a subscriber can count
  a read. A delivery waits as long as a provider's `Retry-After` asks before trying again. Each
  process names itself, and `jadpo schedules` shows which one holds a schedule.
- **Sign in with GitHub** through a `Driver.github` connection, with `client_id:` and `credential:`.
- **More from provider packages.** A failure can say how its provider writes it, with
  `wire_status:` and `wire_name:`. A body can be sent as a form or in parts, with
  `Protocol.form_http` and `.multipart_http`. A host can hold a placeholder filled from a setting, a
  setting can have a `default:`, and a webhook's field can be read by the package's own `decode:`.
  An input field typed `AnyObject` takes any of your app's object types, for a provider's template
  variables or metadata. Importing a description again keeps a type you renamed.
- **Upgrading packages.** `jadpo package update <name> --plan` lists what an update would reach and
  the compile errors, schema changes and reviews it would bring, and changes nothing. When a newer
  Jadpo finds more in an installed package's own code than the publishing bar did, such as a
  judgement call, `jadpo check` shows one alert about the package and goes on. A package that
  doesn't compile, or breaks a security rule, is still refused. `jadpo package check --previous`
  names the release to compare with.
- **Typed holes.** Write `_` where a value goes, and `jadpo check` answers with `type.hole`: the
  type that goes there and up to five values in scope that fit, with an edit for the closest. A
  project with a hole never checks, tests or builds.
- **UK postcodes and registry names.** The `postal` namespace takes a UK postcode apart:
  `outward_code`, `inward_code`, `area`, `district`, `sub_district`, `sector` and `unit`.
  `names.registry_part` writes a name from code as the package registry does: `AcmeCouriers` is
  `acme-couriers`.
- **Editor and tooling.** The VS Code extension highlights `.jadpo_record` files, and the language
  server shows a record's errors and outline as you edit it. `jadpo check` tells a record edited by
  hand from one that is out of date. Declared names are bold and comments italic in any theme.
  `jadpo routes` and OpenAPI show the generated routes' rate limits, and a refused magic link sends
  `RateLimit` headers. `jadpo build` copies each served API's failure wording beside its
  deployable. Every error page now has the same parts: what happened, why, an example with its
  output, and each fix.

## Fixed

- A library package's functions read its own constants, and a field of an object constant read by
  its name alone, such as `extent.east`, works. Both used to be refused.
- A `File` held inside a list, set, map or object field counts as held, so its bytes stay. In a
  store that a `File` field also names, they used to be deleted a day after they were put.
- An optional field that is `none` is left out of a provider's JSON body, at any depth. It used to
  be sent as `null`, which some providers refuse.
- A secret value given to a provider's operation is sent as itself. It used to reach the provider
  as a `<redacted …>` placeholder.
- After `jadpo package add @jadpo/british-grid`, the hint names the package as you typed it, and
  `package show`, `update` and `remove` take that name. It used to name the package's folder.
- A field declared twice in a type is one `type.duplicate_field`, or `type.duplicate_variant_field`
  in an enum variant, not also `package.wire_name_invalid`. An event, a message or an entity reports
  it the same way.
- The edit `type.mismatch` offers writes every field the value needs, optional ones included.
  Applying it used to give `type.missing_field`.
- Removing a `;` at the start of an indented line keeps the line's indent. The edit used to close
  the block early.
- A download from the registry that a signal interrupts carries on, rather than failing.
- The registry's verifier accepts a `NOTICE` file beside a package's licence, and reports when the
  package's contract recordings were last made. It used to refuse a `NOTICE` and report no date.
- Several errors say what they need: an optional value in a `nearest` order, a `limit:` or a page
  `size:` is no longer told to use `where_present:`, a function calling a query isn't told a query
  may write data, and a generated field set through `patch:` or `when_supplied:` is to be removed
  from there.
